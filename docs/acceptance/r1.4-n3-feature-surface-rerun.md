## 2. 为什么 N3 最终不用模型文本 judge

旧 N3 实际测到的是「**模型怎么描述失败**」，而不是「**shell HTTP 命令是否失败**」：
真实 shell 每次都已被 sandbox 拒绝（deny code 134），但模型措辞在
`不可访问` / `exit 134` / `退出码 134` 之间波动，outer rc 恒为 0 → judge 判据与
措辞耦合，产生 2/2 相同措辞的确定性 FAIL。

本轮改为：解析 exact 0.159.2 JSONL 的 structured `command_execution` item，直接对
**sandbox 内实际执行的 curl 命令**断言 `exit_code == 134`。模型最终回答**完全不参
与判定**（已固化专测：中文/英文/空串/拒绝执行四种文本，结论一致）。

与 N1 的 `--json` 禁令不矛盾：N1 需要「注册工具清单」，JSONL 没有该事件；N3 需要的
是「刚跑完的命令的真实 exit status」，正是 `command_execution` 提供的事实。

## 3. N3 targeted JSONL probe（先 probe 再冻结 parser）

staging-only 调用（certified argv + `--json`），要求模型只执行一次指定绝对 curl：

- outer rc = **0**
- JSONL **10 行，0 行不可解析**
- 生命周期完整：`thread.started` → `turn.started` → … → `turn.completed`
- `command_execution` 出现两次（同 id）：
  - `item.started`：`status='in_progress'`、`exit_code=None`、`aggregated_output=''`
  - `item.completed`：**`status='failed'`、`exit_code=134`**、`aggregated_output=''`
- `command` 真实字段格式（被 shell 包裹）：

  ```
  /bin/zsh -lc '/usr/bin/curl -sS --max-time 8 https://api.github.com/repos/yikart/AiToEarn'
  ```

- **无任何 web_search 调用类 event**
- 实测 deny code = **134**，与冻结预期一致（未触发 STOP 条款）
