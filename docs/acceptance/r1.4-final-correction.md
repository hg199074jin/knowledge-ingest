## 3. P2｜N3 的 web_search JSONL 检测字段错误（BLOCKER，已修）

### 3.1 旧 guard 的漏检

```python
if any(str(e.get("type", "")).endswith("web_search_call") for e in events):
```

但 exact 0.159.2 的真实 JSONL 映射是：

```json
{ "type": "item.started" | "item.completed",
  "item": { "type": "web_search", ... } }
```

顶层 `type` 是生命周期，web search 类型在 **`item.type`**。旧 guard 只看顶层 type，
**可能漏掉真实 WebSearchItem** —— 属于 fail-closed 完整性缺陷（不是隔离失效：N2 已实证
无实时联网）。

### 3.2 修复：结构化 detector

新增 `contains_web_search_event(events)`（`_is_web_search_type` 辅助）：

- 覆盖 item envelope：`type ∈ {item.started, item.completed, item.updated}` 且
  `item.type == "web_search"`；
- 同时保留对顶层 `web_search*` event 名的覆盖（不丢旧 guard 覆盖面），并覆盖
  `web_search_call` / `web_search_begin` 等命名变体；
- **只读 type 字段，绝不对文本做 substring**：agent 最终回答或 deprecation 提示里出现
  `web_search` 字样**不会**触发（避免第二类假阳性 —— 第三轮已实测该字样会由
  `[features].web_search*` deprecation 提示产生）。

原则：任何 structured web_search item 出现 → N3 FAIL，与 query / results / status /
agent 最终回答无关。

| **watch 运行态 PID** | **626** | **1010** | **变化，见下** |

**watch PID 变化的如实归因**：watcher plist 为 `RunAtLoad=true` + **`KeepAlive=true`**
的常驻 agent。检查其日志（仅取元数据与异常签名，未导出内容）发现一次
`ConnectionError: [Errno 61] Could not connect to proxy 127.0.0.1:7897` 连续 5 次
自动重连失败后进程退出，launchd 依 `KeepAlive` 重新拉起 → PID 由 626 变为 1010，
当前运行正常（last exit status `0`，日志持续写入）。

判定：**与 R1.4 无关**。R1.4 全程未读写 V2 plist / code / launchd；staging child env 显式
不含任何 proxy 变量（`PATH=/usr/bin:/bin`，env 仅 `HOME`/`CODEX_HOME`/`PATH`），
不可能影响宿主 V2 进程的网络栈。根因是本机代理端口当时不可达（环境条件）。

Residual（如实记录）：**V2 watcher 的可用性耦合本机代理 127.0.0.1:7897**，代理中断会
导致 watcher 退出并由 KeepAlive 重启。该耦合在 R1.4 边界之外，留给后续运维轮次。
