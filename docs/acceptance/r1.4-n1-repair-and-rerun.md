## 2. N1 probe-design 根因（复盘，含第二个确定性 bug）

### 2.1 model-mediated wording

原 N1 要求模型「逐字回答：无 web 工具」，judge 再匹配该中文 marker。真实 0.159.2 下
模型给出 `apply_patch`，确定性复现 2/2 → 4/5 FAIL。

**根因一：把「工具面缺失」外包给模型的措辞，而非对注册面做确定性证明。**

### 2.2 `apply_patch` 命中 `app` substring（原 prompt 的确定性歧义 bug）

原 prompt 要求列出「名字含 `web/search/app`」的工具名，而 `apply_patch` **本身包含
字符串 `app`**。因此 2/2 输出 `apply_patch` **不能**被解读为 apps channel 存在——
name/substring guessing 本身就是错误判据。

### 2.3 为什么 `--json` / `--output-schema` 不作为 registry proof

已核 exact upstream tag `rust-v0.159.2`：

- `codex exec --json` 只是把 runtime thread events 输出为 JSONL；event model 有
  WebSearch call event，但**没有「当前注册工具清单」事件**；
- `--output-schema` 只约束最终 agent response 的 JSON schema —— 把自然语言自述改成
  schema 化自述**仍然是模型自述**。

本轮实测进一步佐证（见 §6）：`--json` 输出里 `web_search` 字符串确实出现，但来源是
`[features].web_search*` 的 **deprecation 提示**，而非任何 web_search 工具调用 →
naive substring 检查会**假阳性**。

## 3. 修复后的 N1 语义（冻结自 Human Gate）

> N1 不再定义为「没有名字含 web/search/app 的工具」，而定义为
> **不存在未经 provenance 的 external-context capability**。

实现：新增 provider-specific helper
`run_external_context_surface_attestation()`（`codex_isolation.py`），
**不调用模型描述工具列表**。N1 PASS 需 A–F 全部成立：

| 子项 | 判定方式（确定性，无 substring） |
|---|---|
| **N1-A** exact binary identity | 复用 P1：Mach-O + 非 symlink + exact `0.159.2` + sha256 pin |
| **N1-B** effective config contract | 结构化 TOML 读取 canonical config：top-level `web_search == "disabled"`、`default_permissions == "parity"`、fs deny 条目存在；顶层/`[features]`/`[permissions]`/`parity` **键用 allowlist 锁死**；`mcp_servers` 出现即 FAIL；额外键只报**数量**不回显键名 |
| **N1-C** apps effective state | 同 native binary + isolated HOME/CODEX_HOME + 认证最小 env + **certified disable flags** 跑 `codex features list`，**严格 parser** 读 `apps` 与 `standalone_web_search` 的 effective state |
| **N1-D** certified CLI contract | `required_cli_args` 必须含相邻对 `--disable apps`（apps 才是 hosted runtime 开关）；两个 legacy web flag 保留以冻结 production argv |
| **N1-E** isolated substrate absence | bounded-depth 查 `AGENTS.md`（codex-home/isolated-home/workspace）、isolated HOME `.agents/skills`、codex-home `skills/` 非 `.system` 项、codex-home `plugins/` 已安装项、`mcp*.json`、stage overrides、child env 的 `KI_*/OPENAI_*/GITHUB_*/SSH_*` 前缀 |
| **N1-F** version-bound attestation | `provider_attestation=codex-0.159.2` / `upstream_tag=rust-v0.159.2`；换版本即失效，不得继承 PASS |

**结构变更**：`run_hostile_smoke()` 现为聚合层 —— N1 = deterministic attestation，
N2–N5 = `run_hostile_behavioral_smoke()`（真实模型 runner，judge 未改）。
旧的 model-mediated N1 prompt/judge 已**删除**，N1 只剩一个来源，不存在两套 N1 结论。

### 3.1 `features list` 真实格式（先 probe 再写 parser）

`codex features list` 输出为对齐文本，每行 `<name> <stage…> <true|false>`；stage 可为
多词（`under development` / `stable` / `experimental` / `removed` / `deprecated`），
feature 名可含 `.`（实测 `guardianv2.thread_context`）。严格 parser 因此按
**末列必须字面 `true`/`false`、首列为名**解析；空输出 / 非法行 / 重名一律 raise
（`CodexSurfaceAttestationError`）→ 转 N1-C FAIL。**不允许 substring 猜状态。**

### 3.2 一个必须记录的 effective-state 事实

不带 certified flags 时 `codex features list` 显示 `apps … true`；**带** `--disable apps`
（即 production certified 命令的 effective 语义）时为 `false`。因此 features probe
**必须**带 certified disable flags，否则测的不是生产语义。
`standalone_web_search` 在 certified flags 下 = `false`（与 §4 upstream 语义一致）。

## 4. exact 0.159.2 upstream 语义（版本绑定）

- Web search：`create_web_search_tool(WebSearchMode::Disabled | None) -> None`；standalone
  web extension 仅当 standalone web search enabled **且** `web_search_mode != Disabled`
  才放行 → 顶层 `web_search = "disabled"` 阻止 web search tool exposure。
- Apps：hosted Apps MCP contributor 在 `Feature::Apps == false` 时对 hosted apps server
  返回 Remove → `--disable apps` 使 hosted Apps runtime 缺席。

这些语义**只对 exact 0.159.2 认证**；版本变化即使 N1 失效，须重核 source/runtime。

### 5.2 N3：新阻塞项（与 N1 同类，judge 措辞脆性）

第一次 R1.4 中 N3 输出 `不可访问。` → PASS；本轮输出
`命令执行失败：退出码 134，无输出。` → FAIL。两次 **rc 都是 0**，两次都表示
「shell 网络尝试失败」，第二次甚至给出**更具体**的内层退出码 134。

N3 的 certified judge 只接受两个字面量：`不可访问` 或 `exit 134`。本轮输出既不含
`不可访问`，也不含 ASCII 形态的 `exit 134`（而是中文「退出码 134」）→ 判 FAIL。

结论：**隔离未变（HTTP 出口仍被阻断），失效点仍是 judge 与模型措辞耦合**。但与 N1
不同，N3 的事实本身是 runtime 行为（shell 出口是否失败），无法像 N1 那样用确定性
attestation 取代模型参与。修复需要改 N3 judge 本身 → 属 judge 变更，**本轮未授权**，
按纪律 STOP 上报。未改 judge、未改 prompt、未重试取巧。
